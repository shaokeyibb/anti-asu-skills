# 凭证核验的公开查询源

按凭证类型列出可用的权威公开查询渠道，以及各自的覆盖局限——**知道一个源查不到什么，比知道它能查到什么更重要**，因为这决定了"查不到"该如何解释。

---

## 零、开始之前：先确认当前日期

**不可跳过。** 本文件中多条规则依赖"现在是什么时候"：

- **专利 18 个月未公开期**——决定"查不到"是正常还是异常；
- **证书有效期**——决定该认证是否已过期；
- **论文录用与见刊的时滞**——决定"已录用未见刊"是否合理；
- **竞赛榜单年代**——决定榜单下线是否有合理解释。

**跳过这一步最典型的后果**：把一项处于正常未公开期的专利误判为疑点。这是纯粹由流程疏忽造成的、对候选人不利的错误，必须避免。

从对话上下文获取当前日期；上下文没有时直接询问用户或读取系统日期。**不要凭训练数据推测当前是哪一年。**

## 一、论文

| 查询源 | 覆盖范围 | 局限 |
| --- | --- | --- |
| DBLP | 计算机领域会议与期刊，作者页聚合完整 | 只覆盖 CS；Workshop 收录不全 |
| Google Scholar | 覆盖最广，含预印本、学位论文 | 收录宽松，含未经同行评审内容；作者页可自行编辑，**不能作为权威源** |
| Semantic Scholar | 覆盖广，有引用关系 | 同上，收录宽松 |
| arXiv | 预印本 | **预印本 ≠ 已发表**，这是核验的关键区分点 |
| ACM DL / IEEE Xplore / SpringerLink | 各自出版物的权威源 | 需分别查询；部分内容需订阅 |
| 各会议官网的 Accepted Papers 列表 | 最权威，能区分主会/Workshop/Poster | 老届次页面可能已下线 |
| 中国知网 / 万方 | 中文期刊与学位论文 | 需订阅；不覆盖国际会议 |

**级别核验**：会议/期刊的分级（如 CCF 推荐目录、JCR 分区）需查对应的官方目录，且要注意**分级是按年份变化的**——应对照论文发表当年的目录，而不是当前版本。

**关键区分点**（这是论文核验最有价值的部分）：
- 预印本 / 投稿中 / 已录用 / 已见刊 —— 四个状态完全不同；
- 主会 Full Paper / Short Paper / Poster / Workshop / Demo —— 分量差异极大；
- 第一作者 / 共同一作（需论文中有明确标注）/ 其他作者 / 通讯作者。

## 二、专利

| 查询源 | 覆盖范围 | 局限 |
| --- | --- | --- |
| 国家知识产权局专利检索系统 | 中国专利，含法律状态 | 申请后 18 个月内未公开的查不到 |
| Google Patents | 多国专利，界面友好 | 法律状态更新有延迟，以官方源为准 |
| Espacenet | 欧洲专利局，覆盖多国 | 中文检索体验一般 |
| WIPO PATENTSCOPE | PCT 国际申请 | 同上 |

**必须核对的字段**：
- **法律状态**：实质审查中 / 已公开 / 授权 / 驳回 / 撤回 / 失效（未缴年费）。"授权"是唯一能称为"拥有专利"的状态；
- **专利类型**：发明专利 / 实用新型 / 外观设计。三者审查严格程度差异极大，发明专利含金量最高；
- **发明人顺序**；
- **申请日与授权公告日**。

**18 个月规则（极其重要）**：中国发明专利自申请日（或优先权日）起满 18 个月才公开。**如果简历声称的申请时间距今不足 18 个月，查不到是完全正常的**，必须标注"处于未公开期"，绝不能作为任何负面信号。

## 三、竞赛

| 类型 | 查询方式 | 局限 |
| --- | --- | --- |
| Kaggle | 用户 profile 页公开显示所有比赛排名与奖牌 | 需区分 Public / Private LB；需确认是个人还是组队 |
| 天池 / DataFountain / Kaggle 类平台 | 赛事页的最终榜单 | 老赛事榜单常下线 |
| ACM-ICPC / CCPC | 官方榜单站点 | 分区赛与总决赛需区分 |
| 蓝桥杯 / 数学建模 / 挑战杯等 | 主办方获奖公示 | 公示常为 PDF 且可能下线 |
| 各大厂算法大赛 | 官方公众号/官网公示 | 归档不稳定 |
| 校内 / 企业内部赛 | **通常无公开信息** | 直接标注 `结构性不可公开核验` |

**核验的重点始终是分母和定语**：
- "前 1%"的分母是报名队伍、有效提交队伍，还是最终榜单队伍？三者常差数倍；
- "冠军"是总决赛冠军，还是分赛区、单赛道、某个子任务的冠军？
- "国家级一等奖"在该赛事中的获奖比例是多少？部分赛事一等奖占比可达 15—20%。

## 四、职业证书与认证

| 类型 | 验证方式 |
| --- | --- |
| 云厂商认证（AWS / 阿里云 / 腾讯云 / Azure / GCP） | 官方证书验证页，需证书编号或验证链接 |
| 语言类（雅思 / 托福 / CET） | 官方成绩查询，需准考证号 |
| 软考 / 计算机等级考试 | 中国计算机技术职业资格网 |
| 安全类（CISSP / CISP / OSCP） | 各发证机构的持证人查询 |
| 项目管理（PMP） | PMI 官方验证 |

**统一处理原则**：绝大多数证书验证需要编号，而简历上通常不写。此时**唯一正确的做法**是标注"需候选人提供证书编号，建议由 HR 在正式背调环节核验"，**不做任何推测**。

**有效期**：云厂商认证、部分安全认证有 2—3 年有效期。过期后严格来说应表述为"曾持有"。这属于极轻微的表述瑕疵，**通常不值得作为疑点上报**，除非该证书是岗位的硬性要求。

## 五、开源社区身份

| 身份声称 | 查询位置 | 实际含义 |
| --- | --- | --- |
| Contributor | 仓库 Contributors 列表 / 合并过的 PR | 贡献过任意代码或文档，**门槛很低** |
| Committer | 仓库 `MAINTAINERS` / `OWNERS` / `CODEOWNERS`，或组织成员列表 | 有直接提交权限，需社区认可 |
| Maintainer | 同上 | 负责模块或项目的维护 |
| PMC / TSC 成员 | 基金会项目页（如 ASF 的 project committee 页面）、项目治理文档 | 治理层，参与项目决策 |
| GSoC / 各类开源实习 | 官方项目页的历年学生名单 | 有明确公示 |

**核验要点**：这几个层级的门槛差异巨大。"Contributor" 与 "Committer" 之间隔着社区的正式提名与投票；"PMC 成员"更是治理身份。**混用层级是明确的夸大**，且因为名单公开，这是可以给出较强结论的。

**必须排除**：
- 有些项目不维护公开名单，只在内部或邮件列表中确认；
- 名单文件可能陈旧；
- 项目对这些术语的定义不统一——有的项目把所有贡献者都叫 Committer。核验前先看该项目的治理文档对术语的定义。

## 六、跨类型的通用纪律

1. **同名是本维度的头号风险**。确认为同一人需要姓名 + 至少两项旁证（单位、时间、研究方向、共同作者、导师）。做不到就写"无法确认为同一人"，不下结论。
2. **只查简历列出的项**。不反向搜索候选人姓名看还能挖到什么——那超出核验范围。
3. **区分"查不到"的三种原因**：未公开期 / 索引不覆盖 / 确实不存在。前两种是中性的，只有第三种才有意义，而要证明第三种，需要该源对该类内容有完整覆盖。
4. **区分"故意造假"与"表述不规范"**。学生常不清楚 Workshop 与主会、申请与授权、Public LB 与 Private LB 的区别。报告应把这种可能性明确写出来。
5. **不核验学历学位**——这属于 HR 通过官方渠道（学信网、学位网、海外院校认证）完成的正式背调，AI 不应从公开信息推断。
