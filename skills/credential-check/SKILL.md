# /credential-check：凭证类主张核验

论文、专利、竞赛、证书是简历里**唯一有权威第三方数据库可查**的部分。这让它们成为核验性价比最高的维度：几分钟就能得到确定性远高于其他维度的结论。

但也正因为可查，纯粹凭空捏造的情况反而少见。更常见的是**口径拔高**——名次的分母被省略、作者顺序被模糊、申请中的专利写成已授权、参与写成主导。本 skill 的重点在这里。

## 边界

- 只核验简历中**明确列出**的凭证。不去数据库里反向搜索候选人姓名看还有什么——那既超出核验范围，也极易因同名而误认。
- 同名歧义是本维度最大的风险。姓名 + 单位 + 时间 + 研究方向四项不能同时对上时，标注"无法确认为同一人"，不做任何结论。
- 查不到 ≠ 造假。大量正当情况会导致查不到：会议未被主流索引收录、论文在预印本阶段、专利处于未公开的申请期（自申请日起 18 个月才公开）、内部竞赛无公开榜单、证书无在线查询入口。
- 不核验学历学位。学历核验有专门的官方渠道（学信网等），由 HR 通过正式背调流程完成，不是本工具的职责，也不应由 AI 从公开信息推断。

## 各类凭证的核验方法

查询源清单见 [references/public-verification-sources.md](references/public-verification-sources.md)。

### 一、论文

**核验步骤**：
1. 按标题在公开学术索引中检索，确认论文存在；
2. 核对**作者列表与顺序**——这是最关键的一项；
3. 核对发表年份、会议/期刊名称；
4. 核对会议/期刊的实际级别与简历声称是否一致。

**高频的口径拔高**：

| 简历表述 | 需要核对的事实 | 落差说明 |
| --- | --- | --- |
| "发表论文 XX（一作）" | 作者列表第一位是否为候选人 | 若为二作/三作 → 明确落差 |
| "发表于 XX 会议" | 是主会论文，还是 Workshop / Poster / 短文 | Workshop 论文写成主会 → 明确落差 |
| "CCF-A 类论文" | 该会议/期刊的实际分级 | 分级不符 → 明确落差 |
| "已发表" | 是否为已录用，还是仅预印本/投稿中 | 预印本写成"发表" → 明确落差 |
| "共同一作" | 论文中是否有共同一作标注（通常有 † 或 * 及说明） | 无标注却声称共一 → 需追问 |

**必须排除**：
- 姓名的拼音/英文写法差异、中英文名不同；
- 期刊/会议改名；
- 论文录用与正式见刊之间有较长时滞，简历写"已录用"是准确的；
- 学生一作在导师课题组中的署名惯例差异（不同领域惯例不同，不宜以单一标准评判）。

**同名判定**：必须结合单位、共同作者、研究方向综合判断。仅姓名相同一律视为"无法确认"。

### 二、专利

**核验步骤**：
1. 按专利名称或申请号在专利公开数据库检索；
2. 核对**法律状态**——这是专利核验的核心；
3. 核对发明人列表与顺序。

**高频的口径拔高**：

| 简历表述 | 实际状态可能是 | 落差 |
| --- | --- | --- |
| "拥有 XX 项专利" | 处于"实质审查中"或"已公开未授权" | 申请 ≠ 授权，明确落差 |
| "发明专利" | 实际是实用新型或外观设计 | 类型不符，明确落差 |
| "第一发明人" | 排在第三、第四位 | 顺序不符 |
| "专利已转化应用" | 无任何实施证据 | 需追问 |

**必须排除**：专利从申请到授权周期长（1—3 年），简历写"已申请"是完全准确的表述；职务发明的发明人顺序由公司决定，个人无法选择。

**查不到时**：发明专利自申请日起满 18 个月才公开。若简历声称的申请时间在 18 个月内，**查不到是完全正常的**，必须标注 `结构性不可公开核验`（处于未公开期）。

### 三、竞赛

**核验步骤**：
1. 找到该赛事的官方榜单或获奖公示；
2. 核对名次、赛道、届次、队伍成员。

**高频的口径拔高**（竞赛是拔高最集中的地方）：

| 简历表述 | 需要核对 | 说明 |
| --- | --- | --- |
| "全国 TOP 1%" | 分母是参赛队伍数还是报名人数？ | 报名与实际提交的队伍数常差数倍 |
| "Kaggle 银牌/前 5%" | Public LB 还是 Private LB？ | Public LB 排名常因过拟合而虚高 |
| "国家级一等奖" | 该赛事的奖项设置与获奖比例 | 有些赛事一等奖比例高达 20% |
| "队长/核心成员" | 队伍规模、官方是否公示分工 | 通常属 `结构性不可公开核验`，转面试追问 |
| "XX 大赛冠军" | 是总决赛冠军，还是分赛区/单赛道冠军 | 常见省略定语 |

**核验重点是"分母和定语"**，不是"有没有获奖"。

**必须排除**：官方榜单已下线（老赛事很常见）；企业内部赛无公开信息；赛事更名或主办方变更。

### 四、职业证书与云厂商认证

**核验步骤**：多数证书有官方在线验证入口，需要证书编号。简历上通常不写编号——此时标注"需候选人提供证书编号方可核验"，转为 HR 在正式背调环节处理，**不做推测**。

**注意**：有效期是常被忽略的一项。部分认证（云厂商认证、部分安全认证）有 2—3 年有效期，过期后表述应为"曾持有"。这是**很轻微的表述问题**，通常不值得作为疑点上报。

### 四点五、公司内部荣誉与平台等级

**形态**：内部技术周刊登榜次数、内部作者等级（如 LVx）、内部创作者榜排名、内部评优、内部认证。

例：「多次登上公司技术周刊，内部作者等级 LV8，年度优秀技术创作者榜第 13 名」。

**核验结论：一律 `结构性不可公开核验`。** 这类荣誉：
- 按定义只有该公司内部系统能证实，**外部查不到是必然的，不是缺口**；
- 评选标准、参与基数、等级体系的含义都不对外公开。

**为什么仍需单独列出**：这类表述**听感很强**（有具体排名、有等级数字、有次数统计），容易被读者当作有分量的外部成就来读，但它的可核验性其实等同于"我在内部很受认可"这句自述。

**正确处理**：
- 标 `结构性不可公开核验`，**这是中性结论，不构成任何负面信息**；
- 不因其无公开痕迹而降低对候选人的评价——内部影响力很可能完全属实；
- 转为面试问题，问**可展开的实质内容**而非排名本身：那些文章写的是什么？有没有公开版本？内部反馈里最有价值的一条是什么？
- **不要追问排名的分母**——那属于公司内部信息，候选人未必有权透露，追问会让候选人陷入尴尬。

**特别提醒**：不同公司的等级体系完全不可比，**绝不能跨公司横向比较**（A 公司的 LV8 与 B 公司的 LV8 无任何可比性）。

### 四点六、公开 Benchmark 与榜单主张

**形态**：声称在某个公开评测基准上取得的成绩，如「在 XX-Bench 上通过率提升 N%」「在 YY 榜单排名第 M」。

**与内部荣誉相反，这一类通常是可核验的**——公开 benchmark 的意义就在于可复现、可比较。

**核验步骤**：
1. 确认该 benchmark 确实存在，且有公开榜单或论文；
2. 核对声称的**具体子集**——很多 benchmark 有多个难度分档或子任务，"在 XX-Bench 上"可能只指其中一个很小的子集；
3. 核对**对照基线**：提升是相对什么测的？是与官方 baseline 比，还是与自己的上一版比？
4. 核对**评测设置**：样本量、是否全量跑、是否允许重试、pass@k 的 k 是多少。

**高频的口径拔高**：

| 简历表述 | 需要核对 |
| --- | --- |
| 「通过率较 baseline 提升 N%」 | baseline 是官方的还是自选的？N% 是相对提升还是百分点？（见 [career-narrative-patterns.md](../resume-audit/references/career-narrative-patterns.md) §2.25） |
| 「在 XX-Bench 上达到 M%」 | 全量还是子集？是否为"难题子集"这类经过筛选的样本？ |
| 「超过 SOTA」 | 对照的是哪个时间点的 SOTA？评测设置是否一致？ |
| 「复现了某论文并提升」 | 复现结果与论文报告值是否一致？"提升"的对照是论文值还是自己的复现值？ |

**必须排除**：
- 内部构建的私有评测集**不适用**本节，归 `结构性不可公开核验`；
- 评测设置的差异可能是完全合理的工程选择，**差异本身不是问题**，问题只在于表述是否让人误以为可与公开榜单直接比较。

### 四点七、论文邻接类表述

**形态**：「借鉴 XX 论文的方法」「复现 YY 论文并提升策略」「基于 ZZ 的思路改进」。

**这类表述本身完全正当**——工程实践中借鉴与复现论文是标准做法，且如实说明出处比不说明更诚实。

**核验要点**：区分三种截然不同的参与深度，简历常不加区分：

| 实际做的事 | 恰当表述 |
| --- | --- |
| 读了论文，用了其中的思路 | 借鉴 / 参考了该方法 |
| 完整复现了论文结果 | 复现了该论文（应能给出复现结果与论文值的对比） |
| 在复现基础上做了改进并验证 | 在该方法基础上改进（应能说明改了什么、效果如何验证） |

**追问方式**：「复现的结果和论文报告的数字差多少？差异的原因分析过吗？」——真正复现过的人对差异有具体认知，因为复现几乎从不与论文数字完全一致。

### 五、开源社区身份

简历常见"XX 项目 Committer / Maintainer / PMC 成员 / TSC 成员"。这类身份多数有公开名单：

- 项目仓库的 `MAINTAINERS`、`OWNERS`、`CODEOWNERS` 文件；
- 基金会的项目成员页面；
- 项目官网的团队页；
- GitHub 组织的公开成员列表。

**核验要点**：
- 名单中有没有候选人；
- **头衔层级是否对应**——"Contributor"（贡献过代码的人，门槛低）与"Committer"（有提交权限）与"PMC/TSC 成员"（治理层）是完全不同的层级，混用是明确的夸大；
- 身份是否仍然有效（有些项目会移除长期不活跃者）。

若名单中查不到，结合 `/github-audit` 的 PR 记录判断实际贡献量级。

## 输出

```markdown
### 凭证核验

| # | 简历表述 | 核验源 | 查到的事实 | 结论 |
| 1 | "一作发表于 XX 会议" | [索引链接] | 作者列表第 3 位；该文为 Workshop 论文 | 部分属实：作者顺序与论文类型均与表述不符 |
| 2 | "拥有 2 项发明专利" | [专利库链接] | 2 项均为"实质审查中"，未授权 | 部分属实：申请中≠已授权 |
| 3 | "XX 大赛全国前 1%" | 官方榜单已下线 | 无法访问 | 待核验：榜单已下线，建议面试确认分母口径 |
| 4 | "XX 项目 Committer" | 仓库 MAINTAINERS 文件 | 名单中存在 | 已核实 |

**同名风险说明**：[逐条说明如何确认为同一人，或标注无法确认]
**未公开期说明**：[对处于专利未公开期等正常查不到的情况，明确说明]
```

## 结论档位的特殊规则

本维度是最容易得到硬结论的，但仍要克制：

- **可以给 `直接矛盾` 的情况**：官方数据库的客观字段与简历表述直接矛盾，且身份归属已确认无疑（如作者列表明确显示第三作者，简历写一作；专利法律状态明确为"审查中"，简历写"已授权"）。这类矛盾可摘录、可复现、无歧义。
- **必须降为 `疑似` 的情况**：身份归属存在同名可能；简历表述有多种解读方式；核验源本身权威性存疑。
- **必须标 `结构性不可公开核验` 的情况**：处于未公开期、榜单下线、无公开索引、需要证书编号而候选人未提供。

**特别提醒**：凭证类问题往往比其他维度更"扎眼"，但很多落差源于**表述不规范**而非故意造假——比如学生不清楚 Workshop 与主会的区别、不知道"申请"与"授权"在简历上的分量差异。报告中应把这种可能性写出来，让面试官自行判断是能力问题、表述问题还是诚信问题。
