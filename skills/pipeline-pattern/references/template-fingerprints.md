# 简历模板指纹提取

本文件说明如何从一份简历中提取可比对的结构特征。

**先明确一件事**：使用简历模板是**完全正当**的，且几乎所有人都在用。识别"用了模板"没有意义；有意义的是识别"多份简历用了**同一套且不常见的**模板 + 同一种句式 + 同一组项目"这种三重叠加。

---

## 一、版式指纹

可从简历的视觉结构提取，即使内容完全不同也能比对：

| 特征 | 提取方式 |
| --- | --- |
| 栏数与布局 | 单栏 / 左右双栏 / 上下分区；侧栏在左还是右 |
| 分区顺序 | 教育、实习、项目、技能、奖项的排列次序 |
| 分区标题样式 | 有无背景色块、色值、是否有横线、字重、是否带图标 |
| 公司/学校标识 | 是否使用 logo 图片、logo 排列位置与尺寸 |
| 联系方式区 | 图标类型（SVG / emoji / 无）、排列（横排 / 竖排）、字段顺序 |
| 照片 | 有无、位置、尺寸比例 |
| 页数与密度 | 页数、每页要点条数、行距 |
| 强调色 | 主色的具体色值 |
| 时间标注格式 | `2023.03—2023.09` / `2023/03 - 2023/09` / `Mar 2023 – Sep 2023` |

**判定**：色值精确一致 + 分区顺序一致 + 时间格式一致，是较强的同模板信号。

**必须排除**：
- 大量流行的开源简历模板被数万人使用。发现雷同时，先搜索该版式是否为公开模板；如果是，**这就完全不构成信号**；
- 同一在线简历平台（如各类招聘网站的简历生成器）的导出格式天然一致；
- 同一学校就业中心推荐的模板。

---

## 二、句式指纹

这是比版式更难伪装、也更能说明问题的维度。

### 提取项

1. **要点条目的平均字数**与**标准差**。模板化产出的标准差极小（每条都在 40—50 字），真实书写的差异较大。
2. **句式骨架**。把要点抽象成结构，如：
   - `[强动词] + [对象] + ，+ [系统能力描述] + ，+ [业务价值] + ，+ [数字]`
   - 统计有多少比例的条目符合同一骨架。超过 70% 值得记录。
3. **动词分布**。列出所有要点的开头动词。模板化产出高度集中在强动词（主导、设计、落地、重构、优化、攻克、搭建），几乎不出现真实工作中占多数的中性动词（参与、协助、维护、跟进、支持、配合）。
4. **数字挂载率**。有多少比例的要点以量化结果收尾。接近 100% 是强信号——真实工作中大量任务是没有干净指标的。
5. **段落节奏**。每段经历的条目数是否高度一致（如每段都恰好 4 条）。

### 词汇指纹

统计高频的"包装型"措辞。这类词的特点是**信息量低但听起来分量重**：

```
链路、闭环、赋能、抓手、心智、体感、治理、沉淀、拉通、对齐、
0→1、从 0 到 1、端到端、全链路、深度参与、核心链路、
提效、降本、可复用、体系化、标准化、规模化
```

**注意**：这些词在真实的行业环境里也被正常使用，尤其在特定公司的文化里。**单份简历用这些词完全不是问题**。只有在多份简历使用**相同的一组低频措辞**时才有比对价值。

---

## 三、项目组合指纹

单个项目类型重合无意义（热门项目本就集中）。有意义的是**组合方式**。

模板化的项目组合通常呈现出**刻意的覆盖设计**——三个项目恰好覆盖三个不同技术方向，形成"全面"的假象。典型组合：

- 一个 AI 方向 + 一个高并发后端 + 一个手写基础组件；
- 一个业务系统 + 一个中间件 + 一个开源贡献；
- 一个"有数据的" + 一个"有难度的" + 一个"有规模的"。

**提取方式**：把每份简历的项目按 [../../project-check/references/boilerplate-catalog.md](../../project-check/references/boilerplate-catalog.md) 的分类归类，比对分类**组合**是否一致。

**必须排除**：
- 同一培养方案下的课程项目自然相似；
- 同一实习团队的成员项目相同——**这是最常见的解释**；
- 热门方向的自然集中。

---

## 四、开源贡献指纹

如果多位候选人的 GitHub 呈现以下共性，是较强的同源信号：

- **贡献的仓库集合高度重合**，尤其是若干个不相关的仓库同时出现在多人列表中；
- **PR 类型一致**（都是 T0/T1 文档类）；
- **时间窗口重合**（都在同一个 1—2 个月内集中提交）；
- **PR 描述的模板措辞一致**；
- **互相之间有 follow / star 关系**（注意：这一项**仅作为同源的旁证**，不得用于推断候选人之间的私人关系，也不得写入报告的个人评价部分）。

**必须排除**：
- 同一开源活动（如 Hacktoberfest、各类开源之夏）的参与者天然会集中在推荐仓库；
- 同一社区/学校的开源兴趣小组；
- 热门项目的 good-first-issue 天然吸引大量新手。

---

## 五、凭证指纹

- 同一竞赛的同一届次、同一赛道；
- 同一批次的证书（同月获得的同一认证）；
- 同一课程/训练营的结业证明。

**这几乎总有正当解释**（同学、同事、同期学员），单独出现时不应记录。只在与其他指纹叠加时作为佐证。

---

## 六、比对与判定

### 相似度分层

| 层级 | 条件 | 处理 |
| --- | --- | --- |
| **强雷同** | 版式指纹 + 句式指纹 + 项目组合指纹 三者均高度一致 | 记录为一组，输出差异化提问建议 |
| **中度雷同** | 句式 + 词汇指纹一致，版式不同 | 记录，但降低结论强度 |
| **弱雷同** | 仅项目类型重合，或仅版式相同 | **不记录**，无信息量 |

### 判定前的强制排除清单

在得出"疑似同一生产线"的结论前，必须逐条排除：

1. □ 是否为同一团队/项目组的成员？（查公司、时间、项目名是否一致）
2. □ 版式是否为公开可得的流行模板？（搜索验证）
3. □ 是否为同一学校/院系/培养方案？
4. □ 是否参与了同一个开源活动或社区？
5. □ 措辞是否为该行业的通用表达？
6. □ 样本量是否 ≥ 5 份？（少于 5 份不做聚类结论）

任何一条未能排除，结论强度就要下调。

---

## 七、结论的表述纪律

**允许的表述**：
> "这三份简历在版式、句式结构和项目组合上高度一致，可能出自同一套简历撰写流程。这不影响对候选人能力的判断，但意味着这些共性表述不具备区分度，建议从以下差异点入手提问。"

**禁止的表述**：
> ~~"这三个人是某培训班批量产出的"~~ —— 无法证实，且对第三方构成不实指控
> ~~"建议对这类简历统一降级处理"~~ —— 这是群体歧视
> ~~"这批简历都是包装出来的，内容不可信"~~ —— 模板 ≠ 虚假
> ~~"识别出使用了 XX 简历工具"~~ —— 无法确证具体工具

**核心立场**：本 skill 输出的是**信息权重调整建议**，不是**人员筛选建议**。
